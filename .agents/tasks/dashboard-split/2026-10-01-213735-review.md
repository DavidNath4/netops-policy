# Split dashboard summary into five independent async widget endpoints

The single `GET /api/dashboard/summary` is replaced by five independent GET endpoints
(`kpi`, `activity-series`, `config-by-operation`, `top-users`, `recent-config-changes`),
each with its own service function and its own `useApi` client method. The dashboard page
now fires all five in parallel in `onMounted`, so a slow widget no longer blocks the rest,
and each widget owns its loading/error/empty state and its own retry. This is a clean
decomposition of the previously reviewed `summary()` aggregation: the SQL fragments, month
deltas, zero-fill, ordering, and safe projection are carried over unchanged, not rewritten.

Watch for: one out-of-scope line in `server/utils/envelope.ts` (a `SELF_DISABLE_FORBIDDEN`
error code) rides along in the branch — it belongs to the earlier self-disable task, is a
correct fix, and touches no dashboard logic (confirmed). No other scope leakage.

**Verdict**: APPROVED

## High-level view

The server split preserves semantics exactly. `getKpi` keeps the single grouped FILTER
scan with month-boundary deltas (count deltas for Total Activity and Config Changes,
percentage-point delta for Success Rate via `rate()`), `getActivitySeries` returns daily/
weekly/monthly together using the same `date_trunc` windows and `'IYYY-"W"IW'` week format,
`getConfigByOperation` zero-fills the fixed four `ROUTE/ADD…ACL/DELETE` via a Map,
`getTopUsers` groups by username ordered by `count(*)` desc limit 8, and
`getRecentConfigChanges` returns the newest-first safe projection with no payloads. The
old `summary()` and `DashboardSummary` are gone and nothing references them.

The five handlers are uniformly thin: `requireAuthenticatedUser(event)` then
`ok(await <fn>(useDatabase()))`, no feature permission, matching the dashboard's common-access
posture and the `audit` handler pattern. Route paths derive correctly from the filenames.

`useApi.ts` exposes exactly the five methods over the envelope-unwrapping `apiGet`, each with
its own return type; the stale `summary()`/`DashboardSummary` block is removed and no other
API section changed.

`index.vue` gives each widget an isolated `{ data, pending, error, loadX }` triplet, fires all
five loads without awaiting them in sequence, and wires each `ErrorState` `@retry` to re-fetch
only that widget. The Daily/Weekly/Monthly toggle switches a computed over the single
pre-fetched `seriesData` with no network call. Visuals match the approved design (KPI cards
with no icons and deltas, bar chart with min-2% height so sparse real days stay visible, config
bars, ranked users, recent feed with inline colored SUCCESS/FAILED label rather than
StatusBadge), tokens only, English copy, no synthesized data.

### Service decomposition preserves aggregation semantics

`dashboard.service.ts` keeps the module-level `inThisMonth` / `inLastMonth` / `isConfigChange`
fragments and the `num()` / `rate()` helpers verbatim, and each of the five exported functions
holds the matching query body from the old `summary()`:

- `getKpi` runs the one grouped scan with `count(*) filter (where …)` for every window and
  returns `totalActivity = { value: totalAll, delta: totalThis − totalLast }`,
  `configChanges = { value: cfgAll, delta: cfgThis − cfgLast }`, and
  `successRate = { value: rate(successAll,totalAll), delta: rate(successThis,totalThis) − rate(successLast,totalLast) }`.
  Success delta stays in percentage points; the other two stay count deltas.
- `getActivitySeries` runs the three series under `Promise.all` with the same windows
  (`-13 days`, `-11 weeks`, `-11 months`) and formats (`'YYYY-MM-DD'`, `'IYYY-"W"IW'`,
  `'YYYY-MM'`), returning `{ daily, weekly, monthly }` — all three in one response so the
  client toggle never refetches.
- `getConfigByOperation` zero-fills `['ROUTE/ADD','ROUTE/DELETE','ACL/ADD','ACL/DELETE']` from a
  `Map` of `${module}/${action} → count`, field name `operation` kept.
- `getTopUsers` groups by `username`, `orderBy(desc(sql`count(*)`))`, `limit(8)`, `username ?? '—'`.
- `getRecentConfigChanges` projects `{ id, module, action, username, status, createdAt }` only,
  `isConfigChange`, newest-first, `limit(8)`, `createdAt.toISOString()` — no JSONB, no secrets.

`count`, `desc`, and `sql` all remain used, so no unused-import failure under strict TS.

### Independent, auth-only handlers

Each handler is three meaningful lines and calls exactly its own service function with
`useDatabase()`, wrapped in `ok()`. All use `requireAuthenticatedUser(event)` only — no
`requirePermission` — which is the correct common-access gate for the dashboard and matches the
original summary handler and `audit/index.get.ts`. Route paths map cleanly from filenames to
`/api/dashboard/{kpi,activity-series,config-by-operation,top-users,recent-config-changes}`.

### Parallel fetch and per-widget isolation on the page

`onMounted` calls `loadKpi(); loadSeries(); loadConfig(); loadUsers(); loadRecent();` with no
`await` between them, so the five requests run concurrently. Each `loadX` sets its own
`pending`/`error` and assigns its own `data`, and each widget block renders its own
`LoadingState` / `ErrorState` (with `@retry="loadX"`, re-fetching only that widget) / `EmptyState`.
There is no page-level wrapper that would hide the other widgets behind one widget's state.

The granularity toggle is a `computed` (`activeSeries`) over `seriesData.value?.daily|weekly|monthly`,
so switching Daily/Weekly/Monthly triggers no network call. `barHeight` floors non-zero bars at
2% of track height, so the sparse real data (the two days with activity) stays visible, and only
existing buckets render — nothing is synthesized.

Visuals match the approved design: three KPI cards with no icons, count deltas and a
percentage-point Success Rate with ▲/▼ colored via `text-ok`/`text-bad`; config bars using
`op.operation.replace('/', ' / ')`; ranked users as `#index+1` + name + count (no role/failed);
and the recent feed uses an inline colored `Success`/`Failed` label (not `StatusBadge`). Only
token utility classes appear — no hex — and copy is English.

### Scope

Changes are confined to the dashboard files plus the one envelope error-code line noted above.
No schema, migration, or dependency change. `LoadingState`/`ErrorState`/`EmptyState` are reused
with their existing props (`message`, `title`/`description`/`icon`, `@retry`), not restyled.

### Not independently executed

Per the task constraint, no typecheck/build/test/git was run; verification is by reading the
files and the coder's note. The branch has not been compiled here, so a genuine TS error would
not be caught by this review — but every symbol, import path, and shape was traced across
service → handlers → `useApi` → `index.vue` and they agree.
